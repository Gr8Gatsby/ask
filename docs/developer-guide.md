## Development setup

**Prerequisites**
- macOS 14.0+, Xcode 16+
- Python 3.11+ (for Python scripts)
- `brew install xcodegen create-dmg gh` (for Mac releases)
- AskMac running (build from `AskMac/` in Xcode or run from the Mac companion app)

**Initial setup**

```bash
git clone https://github.com/Gr8Gatsby/ask.git
cd ask

# Point AskMac at the repo scripts for development
/vault-setup dev    # or manually: set vaultPath in UserDefaults for simple.askmac

# Edit a script in ask/scripts/, then sync it live
/deploy-scripts my-script-id
```

**Vault modes**

| Mode | Path | Use when |
|---|---|---|
| Dev | `<repo>/ask/scripts/` | Iterating on scripts in this repo |
| Prod | `~/.ask/scripts/` | Running stable scripts persistently |

Switch with `/vault-setup dev` or `/vault-setup prod`.

## Writing scripts

### The fastest path: `/ask-script`

Use the Claude Code skill:

```
/ask-script monitor my Homebrew packages and let me upgrade outdated ones from iPhone
```

The skill generates a complete, working script with the correct manifest, MCP client, block emissions, response handling, test mode, and all the non-obvious patterns. Start here.

### Script structure

A minimal script has two files:

```
my-script/
  manifest.json
  main.py          (or any executable: main.sh, my-binary, …)
```

### `manifest.json` reference

```json
{
  "id": "my-script",
  "name": "My Script",
  "version": "1.0.0",
  "description": "One-line description shown in Settings",
  "entry": "main.py",
  "icon": "bolt.fill",
  "icon_file": "icon.svg",
  "schedule": "0 9 * * *"
}
```

| Field | Required | Description |
|---|---|---|
| `id` | ✅ | Lowercase hyphenated. Used as directory name and CloudKit key. Permanent — changing it creates a new script identity. |
| `name` | ✅ | Display name in iOS app and Mac Settings |
| `version` | ✅ | Semver string. Checked on app launch for vault update detection. |
| `description` | ✅ | Shown in Settings and PKG installer component list |
| `entry` | ✅ | Executable filename relative to the script directory |
| `icon` | — | SF Symbol name. Fallback icon if no SVG. |
| `icon_file` | — | SVG file (32×32 recommended). Rendered in iOS app and Mac Settings. |
| `schedule` | — | Cron expression. AskMac fires the script at this time if it's a feed-style check. |

### The MCP client

Scripts communicate with AskMac over stdin/stdout using JSON-RPC 2.0. You do not implement the protocol from scratch — use the MCPClient class generated by `/ask-script` or copy from an existing script.

**Python skeleton:**

```python
#!/usr/bin/env python3
import sys, json, asyncio

# Unbuffered UTF-8 stdout — required, do not remove
sys.stdout = open(sys.stdout.fileno(), mode='w', encoding='utf-8', buffering=1)

class MCPClient:
    def __init__(self):
        self._next_id = 0
        self._pending_calls = {}       # rpc_id -> asyncio.Future
        self._response_callbacks = {}  # block_id -> async callable

    def _write(self, obj):
        sys.stdout.write(json.dumps(obj, ensure_ascii=False) + '\n')
        sys.stdout.flush()

    async def _rpc(self, method, params=None):
        rpc_id = self._next_id = self._next_id + 1
        fut = asyncio.get_running_loop().create_future()
        self._pending_calls[rpc_id] = fut
        msg = {'jsonrpc': '2.0', 'id': rpc_id, 'method': method}
        if params: msg['params'] = params
        self._write(msg)
        return await asyncio.wait_for(fut, timeout=10.0)

    async def initialize(self):
        await self._rpc('initialize', {
            'protocolVersion': '2024-11-05',
            'capabilities': {},
            'clientInfo': {'name': 'my-script', 'version': '1.0'}
        })
        self._write({'jsonrpc': '2.0', 'method': 'notifications/initialized'})

    async def emit_block(self, block_id, block_type, payload, ttl=None):
        args = {'blockId': block_id, 'blockType': block_type, 'payload': payload}
        if ttl is not None: args['ttl'] = ttl
        return await self._rpc('tools/call', {'name': 'emit_block', 'arguments': args})

    async def clear_block(self, block_id):
        return await self._rpc('tools/call', {
            'name': 'clear_block', 'arguments': {'blockId': block_id}
        })

    async def wait_for_block_response(self, block_id, timeout=300):
        q = asyncio.Queue()
        self._pending_blocks[block_id] = q
        try:
            return await asyncio.wait_for(q.get(), timeout=timeout)
        except asyncio.TimeoutError:
            return None

    async def read_stdin(self):
        loop = asyncio.get_running_loop()
        while True:
            raw = await loop.run_in_executor(None, sys.stdin.buffer.readline)
            if not raw: break
            try:
                msg = json.loads(raw.decode('utf-8', errors='replace').strip())
            except json.JSONDecodeError:
                continue
            await self._dispatch_inbound(msg)

    async def _dispatch_inbound(self, msg):
        rpc_id = msg.get('id')
        if rpc_id is not None:
            fut = self._pending_calls.pop(rpc_id, None)
            if fut and not fut.done():
                if 'result' in msg: fut.set_result(msg['result'])
                elif 'error' in msg: fut.set_exception(Exception(str(msg['error'])))
        elif msg.get('method') == 'notifications/message':
            data = msg.get('params', {}).get('data', {})
            if data.get('type') == 'user_response':
                block_id = data.get('blockId', '')
                cb = self._response_callbacks.pop(block_id, None)
                if cb:
                    asyncio.create_task(cb(data.get('value', '')))
                elif block_id in self._pending_blocks:
                    await self._pending_blocks[block_id].put(data.get('value', ''))

async def main():
    client = MCPClient()
    asyncio.create_task(client.read_stdin())  # start before initialize
    await client.initialize()

    # your script logic here

asyncio.run(main())
```

### Critical rules

These cause silent failures if missed:

1. **Unbuffered stdout** — the `sys.stdout = open(...)` line at the top is required. Buffered output will not reach the daemon.
2. **`read_stdin` before `initialize`** — start the stdin reader task before calling `initialize()`, otherwise the handshake response gets lost.
3. **Register callback before `emit_block`** — if you're waiting for a response, set up `wait_for_block_response` before calling `emit_block`, not after. CloudKit can deliver the response before `emit_block` returns.
4. **Isolate subprocess stdin** — if your script spawns subprocesses, redirect their stdin away from the pipe (`stdin=subprocess.DEVNULL`), otherwise they may consume daemon messages.
5. **Handle SIGPIPE** — add `import signal; signal.signal(signal.SIGPIPE, signal.SIG_DFL)` at the top. Without it, a broken pipe kills the script silently instead of raising an exception the daemon can log.

### Test mode

Every script must support a test mode: emit one cycle, then sleep 60 seconds and exit cleanly. AskMac runs scripts with `ASK_TEST_MODE=1` to verify they start correctly.

```python
import os

TEST_MODE = os.environ.get('ASK_TEST_MODE') == '1'

async def main():
    client = MCPClient()
    asyncio.create_task(client.read_stdin())
    await client.initialize()

    await run_check(client)  # emit one cycle

    if TEST_MODE:
        await asyncio.sleep(60)
        print('test mode complete', file=sys.stderr)
        return

    while True:
        await asyncio.sleep(3600)
        await run_check(client)
```

### Swift binary scripts

If your script is a compiled Swift binary (like `brew-monitor`):
- Build with `swift build -c release`
- Sign with ad-hoc signature: `codesign --sign - --force .build/release/my-binary`
- Set `entry` in `manifest.json` to the binary filename
- The binary must communicate over stdio using the same JSON-RPC protocol


## MCP tool reference

### `emit_block`

Write a block to CloudKit. The iOS app renders it within seconds.

```json
{
  "name": "emit_block",
  "arguments": {
    "blockId": "my-script-confirm",
    "blockType": "confirmation",
    "payload": { "title": "Continue?", "options": ["Yes", "No"] },
    "ttl": 300
  }
}
```

| Argument | Type | Required | Description |
|---|---|:---:|---|
| `blockId` | String | ✅ | Unique ID. Re-emitting with the same ID updates the existing block. |
| `blockType` | String | ✅ | One of the type strings in the block reference above |
| `payload` | Object | ✅ | Type-specific payload |
| `ttl` | Number | — | Seconds until auto-expiry |

---

### `clear_block`

Remove a block from the iOS app.

```json
{ "name": "clear_block", "arguments": { "blockId": "my-script-confirm" } }
```

---

### `get_schema`

Returns the payload schemas for all block types as plain text. Useful for inspection and validation.

```json
{ "name": "get_schema", "arguments": {} }
```

---

### `list_terminal_sessions`

Enumerate interactive terminal sessions currently running on the Mac. Returns process name, PID, TTY, working directory, and tab title (from Terminal.app or iTerm2 via AppleScript).

```json
{ "name": "list_terminal_sessions", "arguments": { "filter": "claude" } }
```

```json
{
  "sessions": [
    {
      "pid": 1234,
      "name": "node",
      "tty": "s003",
      "cwd": "/Users/kevin/projects/ask",
      "tab_title": "claude — ask"
    }
  ]
}
```

| Argument | Type | Required | Description |
|---|---|:---:|---|
| `filter` | String | — | Case-insensitive substring filter on process name or tab title |

**Use cases:**
- Find the TTY of a running Claude Code session so your hook script can communicate with it
- Detect when a specific process starts or stops
- Map project directories to running sessions

## Script patterns

### Ambient feed script — scheduled automation, no interaction required

The simplest pattern: run on a schedule, emit what happened, expire automatically. The user stays informed without needing to respond. This is the `brew-monitor` pattern for the happy path.

Use `status` for current state, `feed_item` for a permanent log entry in the Feed tab, `countdown` so the user knows when the next check fires, and `alert` for notable one-time events. None of these need a response.

```python
import uuid, time

CHECK_INTERVAL = 4 * 60 * 60  # 4 hours

async def check(client):
    # Show "checking" state while work is in progress
    await client.emit_block('brew-status', 'status', {
        'label': 'Checking for Homebrew updates…',
        'icon': 'arrow.clockwise',
        'color': 'blue',
    }, ttl=60)

    outdated = get_outdated_packages()
    await client.clear_block('brew-status')

    if not outdated:
        # Ambient status — expires before the next check, no interaction needed
        await client.emit_block('brew-status', 'status', {
            'label': 'Homebrew up to date',
            'icon': 'checkmark.circle',
            'color': 'green',
        }, ttl=CHECK_INTERVAL)

        # Permanent log entry in the Feed tab
        await client.emit_block(f'brew-check-{uuid.uuid4()}', 'feed_item', {
            'title': 'Homebrew check complete',
            'body': 'All packages up to date.',
            'icon': 'checkmark.circle.fill',
        })
    else:
        # Surface a confirmation only when there's something to act on
        await _ask_upgrade(client, outdated)

    # Always emit countdown to next check
    await client.emit_block('brew-next-check', 'countdown', {
        'label': 'Next Homebrew check',
        'time': int(time.time()) + CHECK_INTERVAL,
    }, ttl=CHECK_INTERVAL + 300)

async def _ask_upgrade(client, outdated):
    block_id = 'brew-updates'
    self._response_cbs[block_id] = lambda v: _on_upgrade_response(client, v, outdated)
    await client.emit_block(block_id, 'confirmation', {
        'title': f'{len(outdated)} Homebrew updates available',
        'body': '\n'.join(f'{n}  {i} → {a}' for n, i, a in outdated),
        'options': ['Upgrade All', 'Later'],
    }, ttl=86400)

async def _on_upgrade_response(client, value, outdated):
    await client.clear_block('brew-updates')
    if value != 'Upgrade All':
        return
    await run_brew_upgrade(client)
    # Fire-and-forget alert when done — no response needed
    await client.emit_block(f'brew-done-{uuid.uuid4()}', 'alert', {
        'title': 'Homebrew upgrade complete',
        'body': f'Updated {len(outdated)} packages.',
        'icon': 'checkmark.circle.fill',
    })

async def main():
    client = MCPClient()
    asyncio.create_task(client.read_stdin())
    await client.initialize()

    while True:
        await check(client)
        await asyncio.sleep(CHECK_INTERVAL)
```

**Key blocks for ambient scripts:**

| Block | TTL strategy | When to use |
|---|---|---|
| `status` | Set `ttl` to expire just before the next check | Ongoing state ("Up to date", "Checking…") |
| `feed_item` | No TTL — permanent log entry | "This happened at this time" |
| `alert` | Short TTL or no TTL — dismissed automatically | One-shot notifications for notable events |
| `countdown` | Set `ttl` to expire just after the next check fires | "Next check in 3h 42m" |
| `tile` | Short TTL (~10 min), re-emitted on heartbeat | Home-screen summary badge |

### Supervision script — watching a running process

Browse a list, inspect an item, then act.

## Skills reference

### `/ask-script [description]`

Generates a complete, working script from a description. Knows all block schemas, MCPClient patterns, critical rules, test mode, and manifest format. Always start here for new scripts.

### `/deploy-scripts [id | all]`

Syncs scripts from `ask/scripts/` to the prod vault at `~/.ask/scripts/`, rebuilds Swift binaries, and reloads AskMac. Run after every script edit.

### `/vault-setup [dev | prod]`

Switches AskMac's script vault between the repo directory (dev) and `~/.ask/scripts/` (prod).

### `/prepare-release-mac`

Prepares a Mac (AskMac) release:
1. Shows commits since last `v*` tag, grouped by type
2. Proposes a semantic version bump
3. Writes prose + commit release notes for your review
4. Bumps `MARKETING_VERSION` in `AskMac/project.yml`
5. Adds changelog entry to `docs/spec.md`
6. Commits

### `/release-mac`

Cuts the Mac release after `/prepare-release-mac`:
1. Reads version from `AskMac/project.yml`
2. Confirms with you
3. Creates annotated tag `v{version}`, pushes
4. Prompts you to run `scripts/build-release.sh` for signing and publishing

### `/prepare-release-ios`

Same as `/prepare-release-mac` but for the iOS app — bumps `MARKETING_VERSION` in `ask/ask.xcodeproj/project.pbxproj`.

### `/release-ios`

Cuts the iOS TestFlight release — creates `ios-v{version}` tag, pushes, then prompts you to run `scripts/release-ios.sh`.

## Mac app development

**Key files:**

| File | Responsibility |
|---|---|
| `ScriptManager.swift` | Discovers scripts from vault, spawns/monitors processes, auto-restarts on crash |
| `MCPConnection.swift` | JSON-RPC 2.0 dispatcher — tool definitions, dispatch, schema text |
| `BlockService.swift` | CloudKit writes for all block types |
| `ResponsePoller.swift` | Polls CloudKit for user responses, delivers to script via stdin |
| `CloudKitService.swift` | All CloudKit operations (save, fetch, subscribe, purge) |
| `ScriptUpdateService.swift` | Compares bundled vs vault script versions at launch |
| `TerminalMonitorService.swift` | Enumerates TTYs from `ps`, `lsof`, Terminal.app, iTerm2 |

**Adding an MCP tool:**

1. Add the tool definition to `toolsList` in `MCPConnection.swift`
2. Add the case to `dispatchTool()` in `MCPConnection.swift`
3. Add the schema description to `schemaText` in `MCPConnection.swift`
4. Implement the handler and return a JSON-serializable result

**Adding a block type:**

1. Add case to `RKBlockType` enum in `CloudKitSchema.swift`
2. Add CloudKit field mappings in `BlockService.swift`
3. Add `emit_block` handling if the new type needs special server-side logic
4. Update `schemaText` in `MCPConnection.swift`
5. Add iOS renderer (see iOS app development below)
6. Update `docs/blocks.md`

## iOS app development

**Key files:**

| File | Responsibility |
|---|---|
| `RemoteKitModels.swift` | `RKBlockType` enum, payload structs, CloudKit field names |
| `BlockViews.swift` | SwiftUI views for all block types |
| `iOSCloudKitService.swift` | CloudKit queries, block polling (5s), response posting |
| `HomeView.swift` | Main feed of live blocks from all scripts |
| `ScriptDetailView.swift` | Per-script block list, 5s poll loop |

**Adding a block renderer:**

1. Add case to `RKBlockType` in `RemoteKitModels.swift`
2. Add payload struct conforming to `Decodable`
3. Add `case .myNewType: MyNewBlockView(block: block)` to the block dispatch in `BlockViews.swift`
4. Implement `MyNewBlockView` — receives the decoded payload, renders the UI, calls `onResponse` with the user's choice

**Block response pattern:**

```swift
struct ConfirmationBlockView: View {
    let block: RKBlock
    let onResponse: (String) -> Void

    var body: some View {
        // render the block
        Button(option) {
            onResponse(option)   // delivers value to CloudKit response record
        }
    }
}
```

## Release workflow

### Mac

```
/prepare-release-mac          # version bump, release notes, commit
/release-mac                  # tag v{version}, push

# Then locally:
export APPLE_ID="you@example.com"
export APPLE_ID_PASSWORD="app-specific-password"
export APPLE_TEAM_ID="B5J28L8ARB"
./scripts/build-release.sh
# → signs, notarizes, creates DMG + PKG, publishes GitHub Release
```

### iOS (TestFlight)

```
/prepare-release-ios          # version bump, release notes, commit
/release-ios                  # tag ios-v{version}, push

# Then locally:
export ASC_KEY_ID="your-key-id"
export ASC_ISSUER_ID="your-issuer-id"
./scripts/release-ios.sh
# → archives, exports IPA, uploads to TestFlight
```

### Prerequisites for local release builds

**Mac:**
- Developer ID Application + Developer ID Installer certificates in Keychain
- Sparkle tools at `sparkle/bin/sign_update` (download from Sparkle GitHub releases)
- `brew install create-dmg gh`
- Xcode project generated: `cd AskMac && xcodegen generate`
- Sparkle public key filled in `AskMac/Sources/AskMac/Info.plist` (`SUPublicEDKey`)

**iOS:**
- App Store provisioning profile installed in Xcode
- ASC API key at `~/.appstoreconnect/private_keys/AuthKey_{ASC_KEY_ID}.p8`
